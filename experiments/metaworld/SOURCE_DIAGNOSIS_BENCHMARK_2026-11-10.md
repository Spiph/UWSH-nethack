# Benchmark comparison for the failed source-competence gate

Research for [the source diagnosis](https://github.com/Spiph/UWSH-nethack/issues/55), 2026-11-10. This note compares primary papers and official source code. It does not establish why push/pick-place failed, and authorizes no interaction or training. No policy arrays, native constructors, environments or physics were accessed for this research.

The retained run is a custom, visible-goal single-task development protocol: separate SAC learners; 50 source configurations sampled at each 500-step reset; 20 disjoint fixed development configurations; deterministic evaluation; any-time success in complete episodes. Its [frozen configuration](development_2026-11-09.json) uses replay50k, warmup1k, two256-unit ReLU layers, LR3e−4, batch256, automatic alpha, gamma.99, tau.005 and one gradient update per source step. The extension changed the allowed milestones, not these settings. One shared-initialization library and a failed operational gate do not establish a policy-subspace transfer result.

## Concrete pitfalls worth discriminating

**Replay/exploration is a supported mismatch, not a demonstrated cause.** At500 steps/episode,50k replay retains about100 episodes; warmup1k explores only two episodes. With50 reset configurations and uniform sampling, neither observation implies adequate coverage of rare grasp-and-lift states. Root's separate retained-artifact audit reports rare early positive pick-place experiences absent from later buffers; that is compatible with forgetting, but also with a policy that stopped reaching them. Larger replay can preserve experience but does not create it. A1M buffer also increases replay/checkpoint storage substantially; this is not a free change within an existing quota.

**Reaching is not the same physical test as manipulating.** At the pinned Farama3.1.1 commit, XYZ actions are clipped to[-1,1] then multiplied by0.01; the fourth action drives opposed fingers, and positive effort is used in the caging reward as closing. The39-vector contains current18 coordinates, previous18 and goalXYZ; indices4:7 are object position and36:39 the goal. Reaching competence cannot certify correct object/gripper behavior. A second action scale or sign flip would be consequential, but this comparison has found no evidence that ours applies one. [Pinned base environment, `set_xyz_action`, `_get_obs`, `step`, `_gripper_caging_reward`](https://github.com/Farama-Foundation/Metaworld/blob/7ea2b501c4a698c8533cdc55a396fe2734e2649d/metaworld/sawyer_xyz_env.py).

**Reward components distinguish bottlenecks better than return alone.** Push exposes `near_object`, `grasp_reward`, `in_place_reward`, `obj_to_target` and success; success is object-target distance≤0.05. Pick-place exposes analogous components, with success≤0.07 although its reward10 condition uses distance<0.05. Its shaping also depends on caging, closing and lifting. Thus low success can mean failure to approach, cage, lift or transport; a scalar return does not identify which. These functions provide predeclared diagnostic observables without inventing a new task reward. [PushV3 `evaluate_state`/`compute_reward`](https://github.com/Farama-Foundation/Metaworld/blob/7ea2b501c4a698c8533cdc55a396fe2734e2649d/metaworld/envs/sawyer_push_v3.py), [PickPlaceV3](https://github.com/Farama-Foundation/Metaworld/blob/7ea2b501c4a698c8533cdc55a396fe2734e2649d/metaworld/envs/sawyer_pick_place_v3.py).

**Use versioned code over stale prose.** The current official state-space webpage still describes a9D state despite listing indices through17, and its benchmark page describes fixed MT goals. The pinned39D environment code and50-goal generator resolve these inconsistencies. They are documentation pitfalls, not evidence our39D input is wrong. MT1's official train bank is goal-visible and contains50 configurations; adding a disjoint20-goal development bank makes our study custom goal generalization. [State-space page](https://metaworld.farama.org/benchmark/state_space/), [benchmark descriptions](https://metaworld.farama.org/benchmark/benchmark_descriptions/), [pinned MT1/task generation](https://github.com/Farama-Foundation/Metaworld/blob/7ea2b501c4a698c8533cdc55a396fe2734e2649d/metaworld/__init__.py).

## Smallest justified next diagnostic

Finish the retained-evidence audit first: relate source success/return, alpha, actor standard deviation/action saturation, critic losses and rare positive transitions across checkpoints. Distinguish failure on source configurations from failure only on the held-out development configurations. Existing evidence can rank hypotheses but cannot identify a causal hyperparameter intervention.

The first proposed interaction check is the smallest **scripted physical positive control, without learning**: retained source-goal index0 for each failed task, using the pinned official controller. Two complete500-step episodes mean1000 source-diagnostic interactions, zero development/target/final-test interactions and zero optimizer updates. The current resource candidate is one CPU process, at most two environments and two scripted controller instances, five inclusive minutes and8MiB of new artifacts, with one attempt and no retry. It is unapproved until an actual decision resolves [the physical sentinel allowance](https://github.com/Spiph/UWSH-nethack/issues/56). No source actor arrays, SAC or Torch are needed. Freeze exact goals/seeds/code and resource limits before executing; log approach/caging/lift/transport components plus raw and clipped actions. This is a sentinel check, not a performance estimate. Official scripted controllers exist for both tasks, but their presence is not a guarantee they solve every selected configuration. [Push controller](https://github.com/Farama-Foundation/Metaworld/blob/7ea2b501c4a698c8533cdc55a396fe2734e2649d/metaworld/policies/sawyer_push_v3_policy.py), [pick-place controller](https://github.com/Farama-Foundation/Metaworld/blob/7ea2b501c4a698c8533cdc55a396fe2734e2649d/metaworld/policies/sawyer_pick_place_v3_policy.py).

Only if that first check leaves a specific ambiguity should a later proposal pair scripted and frozen actors on one source and one development configuration per failed task (eight500-step episodes,4000 interactions). That larger paired comparison is not the current candidate and has no allocation. Existing retained evidence already establishes learned failure, so it need not be reproduced to test the physical control path.

If the scripted control fails, investigate the task/reset/control path before source learning. If it succeeds while the learned actor cannot approach/cage/lift, that localizes the issue to learned behavior under a functioning sentinel configuration; it still does not identify why learning failed. Only then consider a separately frozen, separately budgeted single-factor replay-capacity comparison, retaining the same initialization, banks and update recipe. Do not infer that more steps, bigger networks, altered entropy or a large sweep is necessary from these sources. The expired original cap and unused calendar time authorize none of these diagnostics.
